# Latency and load: classic request handling vs improved

Generated by `npm run experiment latency`. 10 nodes, 6 clients at 50 requests/s each, 90% reads, 200 keys, N=3 R=2 W=2. Each replica read or write costs a node 5 ms and nodes do one at a time, so a node saturates at 200 operations/s. 10 seeds per row, mean ± standard deviation. The cluster settles for 15 s, then the fault is applied and 60 s are measured. "Ours" turns on hedged reads, latency-aware routing, the 1.25x load cap and hot-key replicas. Latencies are client-side, in ms; a failed request counts as the time until the client gave up.
